# 部署指南

> 目标:把 Agent-Staff 跑起来——一队 agent 常驻飞书、可 @、能定时主动汇报。
> 全程踩过的坑都列在最后,**建议先扫一眼「踩坑清单」再动手**,能省一晚上。

## 0. 前置

| 工具 | 用途 | 安装 |
|---|---|---|
| **zeroclaw** | agent 运行时 | 见 [zeroclaw](https://github.com/zeroclaw-labs/zeroclaw);**飞书渠道要从源码带 `--features channel-lark` 编**(预编译版没飞书),先 `brew install protobuf` |
| **Python 3.9+** | codata(纯 stdlib,无 pip 依赖)| 系统自带 |
| **poppler** | PDF 解析 | `brew install poppler` / `apt install poppler-utils` |
| **tesseract** | 图片 / 扫描件 OCR | `brew install tesseract` / `apt install tesseract-ocr`;读中文:装 `chi_sim` 后设 `export LARK_OCR_LANG=eng+chi_sim` |
| **飞书自建应用** | 每个部门一个 bot | [飞书开放平台](https://open.feishu.cn) 建;海外用 [Lark](https://open.larksuite.com)。**手动步骤见 [飞书接入指南](飞书接入指南.md)** |
| **lark-cli**(可选) | 读飞书原生文档(docx/wiki)时用 | `npm install -g @larksuite/cli`(官方) |

## 1. 建飞书应用 + 填凭证

> 📖 **保姆级手动步骤(建应用 / 开权限 / 事件订阅 / 发布 / 拉群)→ [飞书接入指南.md](飞书接入指南.md)**。下面是要点。

1. 飞书开放平台建**自建应用**,开权限:`bitable`(多维表格)+ `drive`(云空间)+ `im`(机器人收发)+ **事件订阅(长连接 / WebSocket,勾 `im.message.receive_v1`)**,然后**发布**。
   > ⚠️ 机器人权限**只能在后台点**,CLI 给不了。
2. 复制凭证模板,填入 app_id / app_secret:
   ```bash
   cp agent-os/.feishu凭证.example agent-os/.feishu凭证.local
   ```

## 2. 建部门多维表格

```bash
python3 agent-os/scripts/provision.py   # 自动建各部门 Base + 表,token 写回 dept_registry.json
```
> 先 `cp agent-os/dept_registry.example.json agent-os/dept_registry.json`,按你的部门改。

## 3. 配 zeroclaw

```bash
cp agent-home/config.example.toml agent-home/config.toml
```
填:① 模型 api_key(`zeroclaw auth setup-token` 加密存)② 每部门 bot 的 app_id/app_secret ③ codata 的 `feishu_mcp.py` **绝对路径** ④ 白名单 `external_peers`(**群里 @ 用填群 chat_id `oc_...`**,跑 `scripts/list_chats.py` 拿;私聊才用 open_id;或直接跑下面 onboard.py 自动配)。

## 4. 配权限(谁能跟 agent 说话)

按人锁,不是锁群。新员工先拉进部门群,再:
```bash
python3 agent-os/scripts/onboard.py <飞书显示名> <部门alias>    # 自动抓该 bot 视角 open_id → 加进白名单
python3 agent-os/scripts/offboard.py <飞书显示名>               # 离职:逐部门查此人 → 移出所有白名单
```

## 5. 启动

```bash
bash 启动.sh        # daemon 模式(含 cron 调度器),nohup 常驻
```
验证在线:看 `lsof` 的 ESTABLISHED 连接数(**别看 stdout 日志**,见踩坑 ③)。终极验收 = 飞书 @ 一个 bot。

## ⚠️ 踩坑清单(全是真摔出来的,按重要度排)

### ① 飞书长连接全局唯一(最容易「能发不能收」)
每个 bot 的飞书事件长连接**只允许一个进程持有**。被别的进程(如另一个 zeroclaw / OpenClaw / 某 SDK)占着,你的 agent 就**能发消息但收不到**(WebSocket 连上、0 消息)。
- 排查:`lark-cli --profile X event consume im.message.receive_v1 --timeout 3m` 报 "another event bus connected" 就是被占了。
- 解决:杀掉抢占的进程;同一 bot 全局只跑一个。

### ② `channel start` 不带 cron 调度器 —— 主动预警必须用 `daemon`
`zeroclaw channel start` 只起渠道,**不跑 cron**。要定时主动汇报,必须用 **`zeroclaw daemon`**(全家桶:gateway + 渠道 + 心跳 + cron 调度器)。`启动.sh` 已用 daemon。

### ③ 别看 stdout 判断在线 —— 看 ESTABLISHED 连接数
非 TTY 下 zeroclaw stdout 是**块缓冲**,日志常显示空,会误导你以为没起来。判断在线:`lsof -nP -p <pid> | grep -c ESTABLISHED`(每渠道约 1-2 条)或看 `agent-home/data/state/runtime-trace.jsonl`。

### ④ TOML 表头键不能用中文
`[cron.财务周报]` 会报 `invalid unquoted key` → **整个 config 解析失败 → zeroclaw 跑 defaults(全部下线!)**。cron 别名等表头键**必须 ASCII**(`finance_weekly`),中文放 `name=` 字段。

### ⑤ launchd 自启会被沙箱掐网 —— 用 nohup
zeroclaw 的 Seatbelt 沙箱在 launchd 后台判定更严,会掐**出站网络**(codata 能连,但飞书 WebSocket + 模型连不出)。现用 **nohup**(`启动.sh`):扛 SSH 断开 + 关机,**不扛重启**(重启后再跑一遍 `启动.sh`)。绕开沙箱做真自启 = TODO。

### ⑥ 飞书 open_id 每个 app 各看各的
**同一个人,在每个 bot 眼里 open_id 都不一样。** 配白名单时别把 A bot 的 open_id 填到 B bot 的白名单(会不认人)。`onboard.py` 已处理:从「那个 bot 视角」的群成员里抓对应 open_id。

### ⑦ 能直连官方 API 就别 shell 第三方 CLI
读文件/列文件早期 shell `lark-cli`,踩了两个坑:子进程 PATH 找不到 node(`env: node: not found`)、不同版本 CLI 命令语法不一。**改成 urllib 直连飞书 OpenAPI 最稳**(codata 现在就是)。读 PDF/OCR 才 shell 本地工具(pdftotext/tesseract),且按 PATH 找 + 没装给提示。

### ⑧ 改单选字段要带 option id
飞书多维表格改单选(type 3)的选项,必须带每个 option 的 `id`;只传 `{"name":...}` 会**重建选项、把在用记录的值清空**。
