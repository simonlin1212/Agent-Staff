# 架构

## 一条铁律:干活的归干活,经营的归经营

Agent-Staff 不是又一个「让 AI 替你干活」的工具。它是 **经营层**。

```
┌─────────────────────────────────────────────────────────┐
│  你成熟的生产流(Claude Code / 你的创作工具)= 工厂        │  ← 照旧干活,一行不改
│  写代码 · 做内容 · 出产品                                 │
└─────────────────────────────────────────────────────────┘
                        │ 产出成绩(你随口报一句)
                        ▼
┌─────────────────────────────────────────────────────────┐
│  Agent-Staff(zeroclaw + 飞书)= 经营层 / 参谋部           │  ← 只经营,不干活
│  看数据 · 记账 · 汇总 · 提醒 · 管文件 · 控权限             │
└─────────────────────────────────────────────────────────┘
                        │ 落 / 取
                        ▼
┌─────────────────────────────────────────────────────────┐
│  飞书多维表格(Base)= 数据底座 + 共享文件 + IM 壳         │
└─────────────────────────────────────────────────────────┘
```

**硬约束:系统适配你的工作流,绝不为系统改你的工作流。**

## 三层

| 层 | 是什么 | 职责 |
|---|---|---|
| **大脑** | Claude / 你的模型(走订阅或 API) | 理解、叙述、判断 |
| **算盘** | codata MCP(`agent-os/feishu_mcp.py`,纯 stdlib Python) | 求和 / 税 / 汇率 / 日期 / 战报,**确定性计算** |
| **底座** | 飞书多维表格 + 共享文件 | 存数据、存文件、当 IM 壳 |

> **算数交代码、判断交 AI**:数字一律 Python 算好,AI 只负责讲;**只报工具返回的真实数字,不凭记忆编**。这是可信度的根。

## agent 编制

- **1 个 CEO 参谋长**(opus):跨部门聚合 + 算总账。
- **N 个部门 agent**:各管一个部门的飞书 Base;互相看不到对方数据(结构隔离)。
- 每个 agent = 一个人设(`agent-home/agents/<alias>/workspace/`)+ 一个 codata(`--dept` 钉死它的部门)+ 一个飞书 bot 渠道 + 一个白名单。

## 数据怎么进系统(两种)

- **自动拉**:有现成 API 的指标(行情 / GitHub 星 / 网站流量)→ codata 直接拉,永远实时。
- **动嘴记**:其余成绩,你在群里随口报一句 → 部门 agent 调 `log_record` 记进台账。

## codata 提供的工具(每个 agent 都有)

| 工具 | 作用 |
|---|---|
| `get_company_data` | 读本部门所有表 + 自动汇总 |
| `analyze` | 本部门专属战报(数字代码算好)|
| `log_record` | 动嘴记账(返回 record_id)|
| `attach_evidence` | 给某条记录挂凭证 / 依据(附件)|
| `list_files` / `read_file` | 读存储空间文件(PDF 提字、图片/扫描件 OCR)|
| `read_audit` | 看本部门操作日志 |

## 数据访问抽象

`agent-os/datastore.py` 的 `DataStore` 把数据读写抽象掉了(飞书是当前实现)。要换别的后端(Baserow / Teable 等)只需实现同一接口,上层不动。
