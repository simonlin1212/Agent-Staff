# 飞书接入指南(保姆级)

> 这一步**没法自动化**——飞书不开放「代建应用」的 API,必须你亲手去后台点。
> 但跟着点完一遍就懂了,**无编程基础也能跟着做**。海外用户在 [Lark 开放平台](https://open.larksuite.com) 做同样的事。

## 总览:每个部门一个「自建应用」(bot)

Agent-Staff 每个部门 agent = 一个独立的飞书 bot。所以有几个部门,就建几个自建应用(CEO + 销售 + 财务 = 3 个)。下面以建**一个**为例,其余照做。

---

## 第一步:建自建应用,拿 App ID / Secret

1. 打开 **[open.feishu.cn](https://open.feishu.cn)** → 右上角「**开发者后台**」→「**创建企业自建应用**」。
2. 填名称(如「AgentStaff-财务」)、图标 → 创建。
3. 进应用 →「**凭证与基础信息**」→ 复制 **App ID** 和 **App Secret**。
   > 这两个最关键,等下填进 `config.toml` 的 `[channels.lark.<部门>]`。

## 第二步:开权限(应用左侧「权限管理」搜下面这些,勾上)

| 中文名(搜索用) | scope | 用途 |
|---|---|---|
| 查看、评论、编辑和管理多维表格 | `bitable:app` | 读写部门数据表(必需) |
| 查看、评论、编辑和管理云空间所有文件 | `drive:drive` | 读存储空间文件 / 建文件夹 |
| 以应用的身份发送消息 | `im:message:send_as_bot` | agent 给人发消息 / 主动预警 |
| 获取与发送单聊、群组消息 | `im:message` | 接收老板提问 |
| 获取用户在群组中的 ID | `im:chat:readonly` | onboard 抓成员 open_id |
| 获取消息中的资源文件 | `im:resource` | agent 看图(合同照 / 截图) |

## 第三步(最关键,最容易漏):事件订阅 + 发布

1. 应用左侧「**事件与回调**」→「**订阅方式**」选 **长连接(WebSocket)**。
   > ⚠️ 必须是长连接,不是「将事件发送至开发者服务器」(那要你有公网服务器)。
2. 「**添加事件**」→ 搜 **`接收消息`**(`im.message.receive_v1`)→ 添加。
   > ⚠️ **不勾这个,bot 永远收不到 @**(能发不能收的头号原因)。
3. 左侧「**版本管理与发布**」→「**创建版本**」→ 填版本号 → **申请发布**(自建应用一般自动通过或管理员一键过)。
   > ⚠️ **不发布,前面开的权限不生效。**

## 第四步:把 bot 拉进部门群

在飞书里建一个部门群(如「财务群」)→ 群设置 → 添加机器人 → 选你刚建的应用。
> 老板在这个群里 @ 它,就能用了。

## 安装 lark-cli(可选 · 读飞书原生文档时用)

[lark-cli](https://github.com/larksuite/cli) 是**官方**飞书/Lark 命令行工具。Agent-Staff 里它只在一处用到:`read_file` 读**飞书原生文档**(docx / wiki)时兜底。
> PDF、图片、列文件都**不**依赖它(走直连 API + poppler/tesseract)。所以不读飞书文档可以先不装。

```bash
npm install -g @larksuite/cli      # 官方包,提供 lark-cli 命令
lark-cli --version                 # 验证
```

我们用到的命令(代码内部自动调,你一般不用手敲):
| 命令 | 干什么 |
|---|---|
| `lark-cli markdown +fetch --file-token <token> --as bot --format pretty` | 把飞书文档拉成 markdown(`read_file` 内部用) |
| `lark-cli --profile <名> event consume im.message.receive_v1 --timeout 3m` | **诊断「能发不能收」**:报 "another event bus connected" 就是长连接被别的进程占了 |

## 常见坑

| 现象 | 原因 | 解决 |
|---|---|---|
| bot 报 **「机器人能力未激活」**（code 232025） | app 没加「机器人」这个应用能力（只开了 API 权限不够） | 开发者后台 → **添加应用能力 → 机器人 → 启用** → 再**创建版本并发布** |
| bot **能发不能收**(@ 没反应 / 弹「思考中」卡住) | ① 没勾事件订阅 `im.message.receive_v1` ② 没发布 ③ **长连接被别的进程占**（飞书每个 app 只允许一个长连接） | 逐条查;占用诊断用上面的 `event consume`。**③ 的典型症状**:@ 后弹「思考中」不出结果、或**另一个服务用错人设乱答**=连接被别的 bot 服务抢了 → **给这个 agent 换一个专属 bot,别和其它服务共用同一个 app** |
| **@ 有反应,但答非所问 / 像是别的部门在答** | `external_peers` 白名单没匹配上发送方 → 消息落到了默认 agent | ⚠️**关键**:群里 @ 时 zeroclaw 看到的发送方是**群 chat_id(`oc_...`)不是你的 open_id(`ou_...`)**。所以群场景 `external_peers` 必须填**群 chat_id**(私聊才用 open_id)。用 `python3 agent-os/scripts/list_chats.py <部门alias>`(凭证从 config 读,不在命令行传 secret)拿群 chat_id |
| 调用报权限错 | 权限没开 / 开了没发布 | 权限管理补开 → 重新发布版本 |
| `read_file` 读飞书文档报 `env: node: not found` | lark-cli 是 node CLI,子进程 PATH 找不到 node | 把 node 所在目录(如 `/opt/homebrew/bin`)加进 PATH(codata 已自动处理) |

## 海外用 Lark(飞书国际版)——同一套代码,只改两处

Lark = 飞书的国际版(同字节跳动,API 几乎一样,数据存新加坡)。**`lark-cli` 就是同一个工具,不用另装一套**,命令一模一样。海外用户只需:

1. **应用在 [open.larksuite.com](https://open.larksuite.com) 建**(不是 feishu.cn);用 lark-cli 时加 `--brand lark`(默认 `feishu`):
   ```bash
   lark-cli config init --brand lark --name <部门>
   ```
2. **代码 API 域名**:启动前设一个环境变量(默认是飞书,设了就走 Lark):
   ```bash
   export LARK_API_BASE=https://open.larksuite.com/open-apis
   ```

就这两处,其余(建应用 / 权限 / 事件订阅 / config / 启动)完全一样。
